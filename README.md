# Hyper Scape — 歩み値リプレイ

歩み値CSV（ティックデータ）を読み込み、ローソク足と歩み値パネルを時系列で再生するローカルWebアプリ。

## 起動

```bash
npm install
npm run dev     # http://localhost:5173/
```

`public/data/default.csv` を起動時に自動で読み込む。
別の銘柄・日付は右上の **CSVを開く** から選択（UTF-8 / Shift_JIS どちらも可）。

## CSVフォーマット

CSVはhttps://www.brisk.jp/から取り扱っている証券会社経由でアクセスしダウンロードする。

ヘッダー名で列を判定する（`値段` / `株数` / `金額` / `時刻`。価格・数量・時間などの別名にも対応）。
ヘッダーが無い場合は `値段,株数,金額,時刻` の並びとみなす。

```csv
値段,株数,金額,時刻
2781,272300,757266300,15:30:00
2780,100,278000,15:24:59
```

- `public/data/default.csv` があれば起動時に自動で読む
- 新しい順（降順）で出力されていても自動で時系列に並べ替える
- 日付と銘柄コードはファイル名から推定する（`default.csv` → 6330 / 2026-08-28）
- 時刻は JST の壁時計をそのまま UTC 秒として保持し、チャートに同じ時刻で描画する

### 再生エンジンの考え方

- `requestAnimationFrame` で仮想時計を `経過秒 × 倍速` だけ進め、`tick.rt <= 仮想時計` のティックを消化する
- 1フレームあたりの処理数に上限を設け、超えたら時計を巻き戻して取りこぼしを防ぐ
- UI state の書き戻しは 60ms 間隔にスロットリング（チャートへの反映は毎フレーム）
- 巻き戻しシークは 0 から再集計して `setData` で差し替えるため、常に前方再生と同じ結果になる

### 秒未満のジッター

歩み値CSVの時刻は秒までしか無いため、素直に再生すると1秒分の約定が1フレームにまとめて流れる。
かといって均等割（`1 ÷ 件数`）にすると、メトロノームのように不自然な等間隔になる。

そこで `lib/jitter.ts` が、実際の板と同じ「かたまりと空白」を持つ到着間隔を生成する。

- 指数分布から `件数 + 1` 本の間隔を引き、累積して 0〜1 秒に正規化する
- 指数を `BURST = 1.6` 乗して裾を重くし、連続約定（数ms間隔）と空白を作る
- 小数第3位で切り捨て。最後の1本も必ず 0.999 以下に収まり、次の秒へはみ出さない
- 乱数はその秒の値を種にした決定的 PRNG なので、**同じCSVは何度読み込んでも同じ再生になる**

結果は `tick.rt`（replay time）に入り、再生時計だけが参照する。
`tick.t` は実時刻のまま残るので、歩み値の表示時刻もローソクの足の区切りも一切ずれない。

```
1秒に8件あった場合のオフセット (ms)
  均等割  :    0 125 250 375 500 625 750 875
  ジッター:    3   4 309 324 598 717 718 718
```

### テクニカル指標

指標はチャート側（`Chart.tsx`）が `ReplaySink` で受け取った足から計算する。再生エンジンは関与しない。

- **移動平均線 / ボリンジャーバンド** … ローソクと同じ価格スケールに重ねる
- **RSI** … 0〜100 の別スケールなので `chart.addPane()` で専用ペインを開く。
  オフにすると `removePane()` でペインごと畳む

問題は「まだ確定していない最新の足」の終値が毎フレーム変わること。素直に全期間を計算し直すと
1秒足では11,430本ぶんの再計算が毎フレーム走ってしまう。そこで各指標に2つの経路を用意している。

| 経路 | 呼ばれるとき | 中身 |
|---|---|---|
| 一括 | シーク・足変更・指標設定の変更 | 全期間を計算して `setData()` |
| 逐次 | ティック消化のたび | 最新足だけ計算して `update()` |

移動平均とボリンジャーバンドは窓の合計なので、末尾 period 本を見れば足りる。
RSIだけは前の足の平均損益を引き継ぐ再帰計算なので、**確定済みの足までの状態**を保持し、
進行中の足はその状態を壊さずに暫定値を覗く（`rsiPeek`）。足が閉じたら織り込む（`rsiAdvance`）。

この作りにより、**再生で進めた値とシークで作り直した値が完全に一致する**
（実データの全足・全指標・全足で最大差 0 を確認済み）。

### CSVの取り込みと切替

ブラウザからは `public/data` に直接書けないので、開発サーバー側にAPIを置いている（`vite.config.ts`）。

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/api/data` | `public/data` 内のCSV一覧 |
| GET | `/api/data/file/<name>` | CSVの中身 |
| PUT | `/api/data/<name>` | CSVを保存（同一内容なら書き直さない） |

- ファイル名は `basename` を取ってから `.csv` のみ許可するので、ディレクトリの外には書けない
- 取得を Vite の public 配信ではなくAPI経由にしているのは、public 配信が起動時に作った
  ファイル一覧を見るため、**起動後に書いたファイルが `index.html` にフォールバックしてしまう**ため
- 保存でページ全体がリロードされて再生位置が飛ばないよう、`server.watch.ignored` で `public/data` を監視から外している
- `npm run build` した成果物にはAPIは含まれない。その場合は `public/data` の静的配信に自動で落ちるので、
  ビルド時点で置いてあるCSVは読める（取り込みと一覧は使えない）

なお 200本MA のように期間の長い指標は、その本数だけ足が溜まるまで線が出ない。
1秒足の200本MA は約定の詰まり具合次第で数分ぶんの再生が必要になる。
前日ぶんの足を継ぎ足して寄り付きから線を出す案も試したが、価格帯の違うCSVを再生したときに
前日の水準が混ざって指標が壊れるため採用しなかった。

## 約定シミュレータ

### 板

| | |
|---|---|
| 左（薄青） | 売気配。ダブルクリックで売り注文 |
| 中央 | 値段。現在値の行を強調 |
| 右（薄赤） | 買気配。ダブルクリックで買い注文 |
| 両端 | 出している注文。クリックで1件だけ取消 |
| 板の上 | 「一括取消」。左は売り注文、右は買い注文を、新規・返済まとめて取消 |

板は現在値を中央に固定しているため注文チップは値段とともに動く。位置の変わらない一括取消を
併せて置いてあり、こちらは**板の外に出た注文も対象**にする。取消は建玉には影響しない。

上部の「新規／返済」で、その注文が建玉を作るのか閉じるのかが決まる。

| モード | 左（売り） | 右（買い） |
|---|---|---|
| 新規 | 売建（ショート） | 買建（ロング） |
| 返済 | 買建を返済 | 売建を返済 |

ロングとショートは別々の建玉として持つので、**両建てができる**。

### 板データについて

歩み値CSVには板情報が入っていないため、気配数量は `lib/book.ts` で合成している。
現在値から離れるほど厚く、キリの良い値段はさらに厚くなるよう作ってあり、
乱数は値段と秒を種にした決定的PRNGなので**同じ場面を再生すれば同じ板になる**。
実際の板ではないので、数量そのものに意味はない。

値段の刻み（呼値）は出現した値段の差の最大公約数から割り出すので、銘柄ごとの刻みに自動で追従する
（`default.csv` は1円、`qr-285A-20260828.csv` は10円と判定される）。

**板の中央は常に現在値**で、現在値の行は画面上で一切動かない。値段が動くと板全体がスクロールする形になる。
現在値を狙って押せることを優先した作りなので、逆に現在値から離れた行の値段は動く。

そのままだとダブルクリックの1回目と2回目の間に行がずれて別の値段に発注してしまうため、
**板を1回クリックした時点で値段を固定する**。固定中は見出しが「固定中」に変わり、板が枠で囲まれる。

| 固定する | 板の行を1回クリック |
| 固定を解く | 発注する（ダブルクリック）／ 板の外をクリック |

固定中に押し直しても固定値は変わらない（2回目で固定し直すと、その間の値動きぶんずれてしまうため）。
売買気配の振り分けと現在値の強調は固定中も生きている値段を見るので、値段がどこまで動いたかは分かる。

走って板の外に出た注文は板の下に「板外の注文」としてまとめて出す。

### 約定

自分で出す注文は指値。再生ループが1ティック消化するたびに突き合わせる（`useReplay` の `onTick`）。

- 買い指値 … 歩み値がその値段**以下**を付けたら約定
- 売り指値 … 歩み値がその値段**以上**を付けたら約定
- 約定値段は指値。滑りは無い

板の上の「指値注文」で小窓を開くと、売買・新規/返済・値段・株数を打ち込んで発注できる（ダブルクリックと同じ注文）。
小窓は対戦の窓と同じ作法で、見出しを掴んで移動・右下で大きさ変更・「—」で帯に畳める。位置は `settings.csv` に覚える。

### 逆指値（損切り）と利確

「逆指値」の小窓で、損切りと利確を**別々に**オンにできる。オンの間は、板・指値注文どちらから
出した**新規注文すべて**に、建値から設定した幅（円/株）だけ離れた自動の返済が付く
（損切りは `Order.stop`、利確は `Order.profit`）。

- 新規が約定すると、損切りはその値段に `type: 'stop'` の返済注文、利確は普通の指値の返済注文
  （`from` 付き）が自動で板に出る（`matchTick` の `spawned`）
- 売りの逆指値は歩み値がその値段**以下**、買いの逆指値は**以上**を付けたら発動
- 逆指値の約定値段は**発動したティックの値段**。飛んだぶんは滑る（成行と同じ扱い）。利確は指値なので滑らない
- 自動の返済（逆指値・利確）は返済数量の予約に数えない。置いたまま手で返済でき、
  返済で建玉が減ったら余ったぶんは新しいものから削る（`trimCloses`。損切り・利確・手の返済を別々に数える）
- オフにしても出ている注文は残る。小窓の「すべて取消」で掃除できる
- 返済の手段は `Trade.exitBy`（'limit' | 'stop' | 'profit'）。取引履歴に「逆」「利」の印、
  `trades.csv` の「返済種別」列に「逆指値」「利確」と残る

倍速や1約定送り（⏭）でも同じ経路を通るので、×300でもコマ送りでも約定する。
一方**シークは時間を巻き戻すので、建玉・注文・履歴をすべて破棄する**（その先で建てた玉は持ち越せないため）。
足の変更では破棄しない。

手数料・金利・貸株料は考慮していない。

### 損益

| 表示 | 中身 |
|---|---|
| 評価損益 | 買建 `(現在値 − 平均建値) × 株数` ＋ 売建 `(平均建値 − 現在値) × 株数` |
| 確定損益 | 返済で確定した損益の累計（＝取引履歴の合計） |
| 合計 | 評価損益 ＋ 確定損益 |

取引履歴の「CSV」ボタンで保存できる。列は
`銘柄,日付,番号,方向,数量,建玉時刻,建値,返済時刻,返済値,損益,累計損益`。

## チャレンジ（分析）

取引パネル最上部に3つのボタンがある。

| ボタン | 動き |
|---|---|
| チャレンジ | 記録の開始／終了。終了時に記録を保存する（取引が0件のときは保存しない） |
| 分析 | いまのチャレンジをその場で集計して表示 |
| 総合 | **これまでの全チャレンジをまとめて集計**。ここからチャレンジ単位の削除もできる |

シークは自由にできるが**巻き戻した回数を数えていて**、分析画面に「やり直したぶん成績は甘く出ています」と出る。
取引が20件に満たないときも「数字は偶然に振り回されます」と警告する。
記録中に再生するCSVを切り替えると、銘柄が変わるのでそこでチャレンジは区切られる。

### 集計する項目

| 区分 | 項目 |
|---|---|
| A 基本成績 | 取引数・勝敗・勝率・損益・平均損益・総利益/総損失・最大利益/最大損失（全体／ロング／ショート別） |
| B 期待値 | プロフィットファクター・リスクリワード比・1取引あたり期待値・**損益分岐勝率**・**優位性**・損益のヒストグラム |
| C リスク | 最大ドローダウン・最大連勝/連敗・標準偏差・リスク調整後リターン・リカバリーファクター・資金曲線 |
| D 時間 | 平均保有時間（勝ち/負け別）・取引の間隔・発注から約定までの待ち時間・取消数・時間帯別成績 |
| E 執行の質 | MAE/MFE・利益の収穫率・負けの逆行と損切りの位置・勝ちでも耐えた逆行・含み益があったのに負けた数・**利確幅/損切幅のシミュレーション** |

勝率だけでは手法の良し悪しは分からない。B の**損益分岐勝率**（`1/(1+RR)`）と実勝率の差が
プラスかどうかで優位性を判定していて、この符号は総損益の符号と必ず一致する（テストで確認済み）。

E の MAE/MFE は建玉していた区間のティックを走査して出す。トレード中に持ち回るのではなく、
`Trade` に記録した `entryN`〜`exitN` を後から見る。同じ理由で、
指標や VWAP といった相場環境もあとから再計算できる（将来の拡張余地）。

利確幅・損切幅のシミュレーションは「その幅に到達した時点で必ず約定した」前提の概算で、
利確と損切りのどちらが先に触れたかまでは見ていない。

### 記録の蓄積

終了時に開発サーバーのAPIへ送り、`public/data/challenges/` に溜める。

| ファイル | 中身 |
|---|---|
| `challenges.csv` | チャレンジ1回につき1行の要約 |
| `trades.csv` | チャレンジ内の取引1件につき1行 |

`.csv` 以外の名前のディレクトリに置いているので、再生用CSVの一覧（「CSVを選択」）には出てこない。
分析画面の「CSV保存」では、その回ぶんを手元にダウンロードもできる。

| メソッド | パス | 用途 |
|---|---|---|
| GET | `/api/challenges` | 溜まっている記録の中身 |
| POST | `/api/challenges` | 記録を追記（無ければヘッダーから作る） |
| DELETE | `/api/challenges/<id>` | そのIDの行を全ファイルから消す |

### 総合分析

「総合」は溜めた記録を読み直して全チャレンジをまとめて集計する。
**MAE/MFE は保存済みなのでティックを読み直さない**（過去の銘柄のCSVを開いていなくても集計できる）。
CSVはヘッダー名で列を引いているので、あとから列が増えても壊れない。

画面下の「チャレンジ一覧」で行をクリックして選ぶと削除できる。削除は2段階の確認つきで、
押すと `challenges.csv` の要約行と `trades.csv` の取引行の両方から、そのIDの行が消える。

複数の銘柄が混ざっている場合は警告を出す。損益（円）は合算できるが、
MFE/MAE のような「円/株」の数字は値段の水準が違うものを平均してしまうため。

## 練習のための仕掛け

### ランダム再生

同じCSVを繰り返すと値動きを覚えてしまい、練習にならなくなる。🎲 を押すと
**値動きの多い 9:00〜10:00 のどこか**からランダムに再生し直す。押した時点で再生も始まる。

### マイルール

「ルール」ボタンで出す浮きパネル（既定は非表示）。ヘッダーを掴めば動かせ、右下をつまめば大きさを変えられる。
× で閉じ、「ルール」ボタンで戻る。

| ルール | 判定するタイミング |
|---|---|
| トレード回数 | 取引が確定するたび |
| 損切り幅（円/株） | 毎ティック。建玉の含み損を見張る |
| 最大ロット | 発注時 |
| エントリー期限 | 発注時（新規のみ。返済は期限後も自由） |
| 最大損失（確定＋評価） | 毎ティック |
| 連敗 | 取引が確定するたび |
| 次の玉まで（秒） | 発注時（新規のみ） |

破ると**その行が赤く点滅し、警告音が鳴る**。行をクリックすると点滅が消える。
**発注そのものは止めない**（破ったことを自覚するのが目的なので）。
チェックと値は `public/data/challenges/rules.csv` に保存され、次回も引き継がれる。

### ゴースト

同じCSVで最後にやったチャレンジのトレードを、チャートにマーカーで薄く重ねる。
「前回ここで買っていた」を見ながら判断できる。まだ描かれていない足には打てないので、
再生がその時刻に追いつくと出てくる。

### 音

下部の「音」ボタンでリストが開き、**3種類を別々にオン・オフ**できる。用途が違うので独立させてある。

| 種類 | 何が鳴るか |
|---|---|
| BGM | 再生中のBGM（下記） |
| 値動き | 約定が流れるたびの音。株数が多いほど低く大きく、値上がりの約定は高め。高倍速で洪水にならないよう毎秒18発まで |
| 約定 | 自分の注文の約定、ルール違反の警告、お題の達成 |

### BGM

再生中だけ流れる。**チャレンジ中かどうかで編成が変わる**ので、記録の付け忘れ・切り忘れに耳で気づける。

| | 編成 | 1秒あたりの発音 |
|---|---|---|
| 通常 | こもったパッド（和音）＋ゆっくりした低い脈 | 約 0.8 |
| チャレンジ中 | 開いたパッド＋ベース＋ハイハット＋アルペジオ | 約 5.7 |

音数で **7倍**、音量で 2.3倍（`BGM_GAIN`）、波形も `sine`/`triangle` から `sawtooth`/`square`＋ノイズへ変わる。
さらに切り替わる瞬間に**合図**が入る（チャレンジ開始は上昇 330→440→587→880Hz、終了は下降 587→440→330Hz）。

音源ファイルは持たず、WebAudioでその場で合成している。**両モードでテンポと和音進行は同じ**なので、
切り替えが拍の途中でも破綻せず、次の刻みで即座に反映される。

### 対戦bot

3体のbotと同じ歩み値で損益を競う。ラウンド制（10 / 30 / 60分。相場の時間で数える）。

#### 何を競っているのか

過去データの再生なので、**botの売買は値段を動かせない**。板の取り合いにはならないので、
競っているのは判断だけになる。その代わり条件は完全に対等で、言い訳の余地が無い。

#### 先読みができない作り

| | |
|---|---|
| 約定 | `matchTick()` — プレイヤーとまったく同じ関数・同じ指値ルール |
| 判断材料 | 自前の1分足（確定した足＋形成中の足）と、通り過ぎた歩み値だけ |
| 足の種類 | 60秒固定。画面の足種を変えてもbotの判断は変わらない |
| 乱数 | `mulberry32(hash32(...))` で種を固定 |

種を固定してあるので、**同じCSV・同じ開始位置ならbotは毎回まったく同じ動きをする**。
つまりタイムアタックのコースとして成立し、同じ場面にリベンジできる。

ロットはプレイヤーの設定に合わせる（あなたが1,000株なら、botも1,000株で入る）。

#### 助走

ラウンド開始時、**そこまでに流れ終わったティック**でバンドと値動きの大きさだけ作らせる
（`warmBot()`）。売買はしないので成績はゼロから始まる。これを飛ばすと、
逆張りはバンドを持たないまま、ブレイクは高安の水準を持たないまま開始してしまう。
プレイヤーがチャートで見ているのと同じ「過去」なので、先読みには当たらない。

#### 3体

| bot | 判断 | 強い | 弱い |
|---|---|---|---|
| 逆張り | ボリンジャーバンド(10本, 1.7σ)の外に出たら逆を張り、中心へ戻るのを狙う | レンジ | トレンド |
| ブレイク | 直近6本の高安を抜けたら付いていく。狭すぎる持ち合いの抜けは無視 | トレンド | レンジ |
| スキャル | 直近240約定の売買の偏り(62%)に乗って、数ティックで逃げる | 出来高の多い時間 | 閑散 |

**弱点が正反対になるように選んである。** どのbotに負けたかで、その日がどんな相場だったかが分かる。

#### 撤退・利確の幅は値幅で測る

ティック数で固定すると、値動きの大きさが違う銘柄でまるで別物になってしまう
（同じ「10ティック」が、ある銘柄では0.4%、別の銘柄では3%になる）。
そこで直近14本の1分足の平均値幅(ATR)を持ち、その倍数で決めている。
銘柄にも時間帯（寄り付きと昼過ぎ）にも自動で追従する。

撤退は逆指値が無いので、**条件が続くあいだ毎ティック現値に指値を置き直す**ことで代用している。
相場を跨いで置く（数ティック譲る）と毎回その幅を確実に損するので、かえって成績が落ちる。

#### 難易度

先読みや手数料ではなく **反応の遅れ** で付ける。合図が出てから何秒後に注文を出すか。

| | 遅れ |
|---|---|
| かんたん | 基準の2.4倍 |
| ふつう | 基準どおり |
| むずかしい | 基準の0.4倍 |

同じ合図で3体が一斉に動かないよう、種を固定した揺らぎ(±15%)を足している。

#### 見え方

botの未約定の注文は**板の行の外端に色の点**で出る。板に映らない値段のものは板の下に
「botの待ち」として一覧で出す。利確の指値は現在値から離れたところに置かれるので、
これが無いと建玉中のbotがどこで待っているのか一切見えない。

売買の中身は **`components/BotBoard.tsx`（botの売買パネル）** に出す。3体ぶんを同じチャートに
重ねると読めなくなるので、メインチャートには出さない（メインに残るのはゴーストだけ）。

botごとに小さな**ローソク足**があり（足の種類はメインの設定と同じ）、その上に
**建てた値段から返した値段まで1本の線**を引く。赤が勝ち、青が負け、建玉中は破線。
横位置は「その時刻がどの足に入るか」で決めるので、ローソクと売買の印がずれない。

図はインラインSVG。チャートライブラリを3つ増やす必要がない。
枠の横幅を実測して `viewBox` をそのピクセル数にしている
（決め打ちの viewBox を `preserveAspectRatio="none"` で引き伸ばすと、
横だけ1.8倍に潰れてローソクが読めなくなる）。

下の一覧には **いくらで建てて、いくらで返して、1株あたり何円、合計何円** を並べる。
「勝った / 負けた」だけでなく金額が読めないと、botの型を真似ようがないため。

スコアボードと売買パネルはどちらもヘッダーを掴んで移動、右下をつまんで大きさ変更ができる。
売買パネルは **—** でヘッダーだけの細い帯まで畳める。位置・大きさ・畳んだ状態は保存される。

#### バランス

3銘柄 × 30分ラウンド33回での通算（損益は「呼値×100株」を1点として銘柄をまたいで比較）:

| bot | 1ラウンド平均 | 勝率 | 取引回数 | ラウンド勝利 |
|---|---|---|---|---|
| 逆張り | +2.61点 | 43% | 2.6回 | 33% |
| ブレイク | +1.97点 | 44% | 2.2回 | 24% |
| スキャル | +3.03点 | 61% | 20.6回 | 42% |

どれか1体が勝ち続けないように調整してある。勝者が場面ごとに入れ替わるからこそ、
「誰に負けたか」が情報になる。

### 今日のお題

日付を種にした決定的な出題なので、同じ日なら何度開いても同じお題が出る。
利益目標・勝率・大負けしない・片方向縛り・ドローダウン制限の5種類から選ばれる。
達成すると緑になり、ファンファーレが鳴る。

### ボタンの解説チップ

チャレンジ・分析・総合・ルール・ゴースト・お題 の6つは、**カーソルを0.5秒重ねると解説が出る**。
ブラウザ標準の `title` は遅いうえに書式が持てないので、`components/Hint.tsx` の `useHints` で自前に置き換えた。

要素を包まず、返ってきた props をボタンにそのまま広げる形にしてある。既存の flex 行のレイアウトを
崩さずに済むのが理由。位置は `position: fixed` で、画面の端からはみ出さないよう中心を丸めている。
ゴーストだけは前回の記録が無いときに一行足して、押しても何も起きない理由を書いている。

## 設定の記憶

`public/data/challenges/settings.csv` に「項目,値」の2列で保存する。マイルールと同じ仕組み。
起動のたびに選び直すのが面倒なので、次の6つを丸ごと覚えている。

| | 項目 |
|---|---|
| インジケーター | MA(表示・本数) / BB(表示・本数・σ) / RSI(表示・本数) |
| 足 | 足の秒数 |
| 再生 | 倍速・昼休みスキップ |
| 音 | BGM / 値動き / 約定 |
| 歩み値 | 開閉・大口の閾値 |
| 対戦 | 難易度・ラウンドの長さ・スコアボードとbot売買パネルの位置と大きさ・畳んだ状態 |
| 配色 | テーマのid |

読み込みが済むまでは書き戻さない。起動直後の既定値で保存済みの設定を潰さないため。
書き込みは500msまとめる（倍速ボタンの連打で毎回書かないように）。
キー引きで読むので、項目が増減しても古いCSVが壊れない。

## 配色テーマ

無地: midnight（既定）/ spring / summer / fall / winter / crazy rainbow / wild jungle /
ghost mansion / happy purple / japan / usa / god zeus / rising sun / casino / death metal /
egypt / atlantis / random

柄物: super mario / doraemon / sunset drive / brick alley / to the moon / lava / retro RPG / 億り人

色は **index.css の CSS変数だけ**が出どころ。面や文字の階調は `color-mix()` で
`--bg` と `--fg` から作っているので、テーマが指定するのは実質7色だけで済む。

```css
--panel:  color-mix(in srgb, var(--fg) 4%,  var(--bg));
--border: color-mix(in srgb, var(--fg) 16%, var(--bg));
--muted:  color-mix(in srgb, var(--fg) 60%, var(--bg));
```

`--bg` と `--fg` を入れ替えれば混ざる向きも自動で反転するので、白地のテーマ（春・冬）も
同じ式のまま成立する。テーマを1つ足すのは `lib/themes.ts` に数行書くだけ。

チャート（lightweight-charts）は文字列の色しか受け取れないので、`lib/colors.ts` が
隠し要素に `color: var(--x)` を当てて、ブラウザに `color-mix()` を解決させてから読む。
テーマを変えたら `refreshPalette()` で読み直し、枠・ローソク・出来高・指標に当て直す。

配色の適用は**副作用ではなくレンダー中**に行う。`useEffect` だと子（Chart）の副作用のほうが
先に走ってしまい、差し替わる前のCSS変数を読んでチャートだけ前の色のまま残る。

### 柄物

柄は `--bg-art` に `background` の層をそのまま書く（グラデーションや `url()`、先頭が手前）。
`.chart-wrap` が `background: var(--bg-art), var(--bg)` で敷き、チャート本体（canvas）の背景は
透明にしてあるので、ローソクの後ろに柄が透ける。板や歩み値は不透明なパネルのままにして、
数字の読みやすさは守る。

レンガや星のように CSS のグラデーションで書きにくい絵は、SVG を data URI にして `url()` で渡す
（`lib/themes.ts` の `brickTile` / `dotTile`）。点の座標は固定で、乱数は使わない。
チャートの下端はいつも時間軸なので、地面のような絵は `AXIS_H` ぶん浮かせてある。
ローソクを読ませるため、柄は地と近い明るさにとどめ、派手な色は小さな絵に限る。

retro RPG だけは色に加えて CSS も持つ（`[data-theme='retro-rpg']`）。角を落として白い枠にし、
チャートを二重線の窓で囲む。

## 画面を広く使う

ヘッダー右端の ▲ とフッターの ▼ でそれぞれ畳める。**帯の何もないところをクリックしても畳める**
（ボタン・入力・セレクトの上では効かない）。畳むと16pxの帯だけ残り、そこを押すと戻る。帯には畳んでいる間も要る情報（銘柄と現在値／時刻とファイル名と倍速）を出す。
歩み値と合わせて全部畳むと、チャートの高さは 717px → 831px（約16%増）になる。

## 機能の説明

画面右下の「説明」を押すと、各機能の解説が開く。ローソク足・板・ロングとショート・
評価損益と確定損益・移動平均線・ボリンジャーバンド・RSI は**図で説明**していて、
図はすべてインラインSVGなので外部画像を持たない。
